# 性能优化报告 - 第十六轮：预分配优化

## 概述

第十六轮性能优化主要针对动态分片模块中的内存分配热点进行优化，通过预分配Vec和HashMap的容量，减少动态扩容带来的性能开销和内存碎片化。

## 优化背景

在动态分片操作中，多个方法频繁创建和扩容集合类型，导致：

1. **Vec多次重新分配**：在收集路径列表时，Vec的容量随元素增长而多次重新分配
2. **HashMap多次扩容**：在收集所有路由时，HashMap的容量随元素增长而多次扩容
3. **内存碎片化**：频繁的分配和释放导致内存碎片化
4. **性能开销**：每次扩容都需要复制现有元素到新的内存位置

## 优化内容

### 1. 新增预分配优化的路径列表方法

**位置**: `src/core/dynamic_sharding.rs`

新增 `list_paths_with_capacity` 方法，使用 `Vec::with_capacity` 预分配容量：

```rust
/// 获取所有路径（带预分配容量优化版本）
///
/// 当已知路由数量时，使用此方法可以避免Vec的多次重新分配
pub fn list_paths_with_capacity(&self) -> Vec<String> {
    let count = self.metrics.route_count;
    let mut paths = Vec::with_capacity(count);
    paths.extend(self.inner.list_paths());
    paths
}
```

**优化效果**：
- 避免Vec的多次重新分配
- 减少内存拷贝操作
- 降低内存碎片化

### 2. 优化获取所有路由方法

重构 `get_all_routes` 方法，新增 `get_all_routes_with_capacity` 方法：

```rust
/// 获取所有路由（带预分配容量优化版本）
///
/// 使用预分配的HashMap容量，减少哈希表扩容开销
pub fn get_all_routes_with_capacity(&mut self) -> HashMap<String, Box<dyn RouteEntry>> {
    let count = self.metrics.route_count;
    let mut routes = HashMap::with_capacity(count);
    for path in self.list_paths_with_capacity() {
        if let Some((route, _)) = self.find(&path) {
            routes.insert(path, route.clone_box());
        }
    }
    routes
}
```

**优化效果**：
- 预分配HashMap容量，减少哈希冲突
- 避免哈希表的多次扩容
- 提升批量路由收集性能

/// 获取所有分片的指标
pub fn get_all_metrics(&self) -> Vec<ShardMetrics> {
    let count = self.shards.len();
    let mut metrics = Vec::with_capacity(count);
    for shard in &self.shards {
        let guard = shard.read().unwrap();
        metrics.push(guard.metrics().clone());
    }
    metrics
}

## 技术原理

### 预分配的优势

1. **减少内存分配次数**：一次性分配足够容量，避免多次重新分配
2. **减少内存拷贝**：避免在扩容时复制现有元素到新内存位置
3. **降低内存碎片化**：减少小块内存的频繁分配和释放
4. **提升缓存局部性**：连续的内存布局提升CPU缓存命中率

### Vec::with_capacity

```rust
let mut vec = Vec::with_capacity(100);
// 立即分配100个元素的容量，无需多次扩容
```

### HashMap::with_capacity

```rust
let mut map = HashMap::with_capacity(100);
// 预分配足够容量，减少哈希冲突和扩容
```
