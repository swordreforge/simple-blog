# 动态路由组主要入口设计方案

## 1. 需求分析

### 1.1 当前问题
在动态路由管理中，经常需要创建一组相关的路由（如：一个功能模块的多个子页面），目前每个路由都需要单独配置是否在快捷操作栏中显示，导致：
- 快捷操作栏过于拥挤
- 管理员需要为每个路由单独设置
- 用户界面不够简洁友好

### 1.2 用户期望

- 一组相关的动态路由只显示主要入口在快捷操作栏目
- 其他相关路由隐藏，通过主要入口访问
- 简化管理，提高用户体验

### 1.3 应用场景示例
**场景 1：用户中心模块**
- 主要入口：`/user/profile`（显示在快捷菜单）
- 相关路由：`/user/settings`、`/user/notifications`（不显示在快捷菜单）
- 访问方式：通过 `/user/profile` 页面中的导航跳转

**场景 2：博客管理模块**
- 主要入口：`/admin/blog/posts`（显示在快捷菜单）
- 相关路由：`/admin/blog/categories`、`/admin/blog/tags`、`/admin/blog/comments`（不显示在快捷菜单）

## 3. 设计方案

### 3.1 方案概述

引入"路由组"（Route Group）概念，通过在 `DynamicRoute` 模型中添加独立字段实现：
- `group_id`: 路由组 ID（同一组路由共享，可选）
- `is_primary_entry`: 是否为主要入口（只有主要入口显示在快捷菜单，可选）
- `metadata`: 继续用于存储辅助信息（如图标、描述等）

**设计原则：**
- **职责单一**：`metadata` 只用于存储辅助信息，不存储业务逻辑字段
- **性能优化**：避免 JSON 解析，提高查询性能
- **向后兼容**：字段为可选，不影响现有功能

### 3.2 数据结构设计

#### 3.2.1 扩展后的 DynamicRoute 模型
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DynamicRoute {
    /// 路由ID
    pub id: Option<i64>,
    /// 路由名称（管理员可见，便于识别和管理）
    pub route_name: Option<String>,
    /// 路由类型（决定路由的存储和读取方式：database/memory/file）
    pub route_type: RouteType,
    /// 路由路径（支持Ant风格通配符，如 /api/**、/user/*）
    pub path: String,
    /// 处理器类型（redirect、static、proxy、custom）
    pub handler_type: HandlerType,
    /// 处理器配置 (JSON)
    pub handler_config: serde_json::Value,
    /// 内联模板内容（存储模板文件的实际内容，支持HTML/JS/CSS/SVG等纯文本格式）
    pub inline_template: Option<String>,
    /// 模板文件路径（相对于二进制文件的配置模板文件路径，当route_type=file时使用）
    pub template_path: Option<String>,
    /// Content-Type 提示（可选）
    pub content_type_hint: Option<String>,
    /// 是否启用
    pub enabled: bool,
    /// 优先级 (数字越小优先级越高，与Java设计一致)
    pub priority: i32,
    /// 创建时间
    pub created_at: DateTime<Utc>,
    /// 更新时间
    pub updated_at: DateTime<Utc>,
    /// 创建者
    pub created_by: Option<String>,

    // ===== 新增字段 =====
    /// 路由组 ID（可选，用于将相关路由归为一组）
    pub group_id: Option<String>,
    /// 是否为主要入口（可选，只有主要入口会显示在快捷菜单中）
    pub is_primary_entry: Option<bool>,

    // ===== 辅助信息 =====
    /// 扩展元数据 (JSON) - 用于存储辅助信息如图标、描述等
    pub metadata: Option<serde_json::Value>,
}
```

#### 3.2.2 更新后的 metadata 结构

- `group_id` 和 `is_primary_entry` 作为独立字段存储，不放在 metadata 中
- `group_name` 和 `group_order` 等辅助信息可以存储在 metadata 中
- 这样设计既保证了性能，又保持了灵活性

### 3.4 前端实现

#### 3.4.1 修改快捷菜单加载逻辑

**quick-actions-dynamic-routes.js 修改：**
```javascript
async function loadDynamicRoutesToQuickActions() {
  const quickActionsContent = document.querySelector('.quick-actions-content');

  if (!quickActionsContent) {
    console.log('未找到快捷操作栏容器');
    return;
  }

  try {
    // 方案1：使用现有的公开 API（推荐）
    const response = await fetch('/api/routes/public?page=1&limit=100&handler_type=static');
    const result = await response.json();

    if (!result.success || !result.data.routes) {
      return;
    }

    const routes = result.data.routes;

    // 过滤出主要入口的路由
    const primaryRoutes = routes.filter(route => {
      if (!route.enabled || route.handler_type !== 'static') {
        return false;
      }

      // 检查路由组信息（直接访问独立字段）
      const groupId = route.group_id;

      // 如果没有路由组配置，使用原有的 metadata.show_in_quick_menu 字段
      if (!groupId) {
        const metadata = route.metadata || {};
        return metadata.show_in_quick_menu === true;
      }

      // 如果有路由组配置，只显示主要入口
      return route.is_primary_entry === true;
    });

    if (primaryRoutes.length === 0) {
      console.log('没有找到主要入口路由');
      return;
    }

    // 创建分隔符（如果已有快捷操作项）
    const existingItems = quickActionsContent.querySelectorAll('.quick-action-item');
    if (existingItems.length > 0) {
      const divider = document.createElement('div');
      divider.className = 'quick-action-divider';
      divider.style.cssText = 'height: 1px; background: rgba(255,255,255,0.1); margin: 8px 0;';
      quickActionsContent.appendChild(divider);
    }

    // 添加主要入口路由快捷操作项
    primaryRoutes.forEach(route => {
      const displayName = route.route_name || route.path;
      const icon = selectIcon(route);
      const groupName = route.metadata?.group_name;

      const actionItem = document.createElement('a');
      actionItem.className = 'quick-action-item dynamic-route-item primary-entry';
      actionItem.href = route.path;
      actionItem.title = groupName ? `${displayName} - ${groupName}` : displayName;
      actionItem.setAttribute('data-route-id', route.id || '');
      actionItem.setAttribute('data-group-id', route.group_id || '');

      actionItem.innerHTML = `
        ${icon}
        <span>${escapeHtml(displayName)}</span>
        ${groupName ? `<small style="display:block;font-size:0.75em;color:rgba(255,255,255,0.6);margin-top:2px;">${escapeHtml(groupName)}</small>` : ''}
      `;

      quickActionsContent.appendChild(actionItem);
    });

    console.log(`已添加 ${primaryRoutes.length} 个主要入口路由到快捷操作栏`);

  } catch (error) {
    console.error('加载动态路由到快捷操作栏失败:', error);
  }
}
```

**改进点：**
- 直接访问 `route.group_id` 和 `route.is_primary_entry`，无需解析 JSON
- 保持向后兼容，无路由组的路由使用原有的 `metadata.show_in_quick_menu` 字段

#### 3.5.2 新增快捷菜单专用 API（可选）

创建 `src/handlers/api_handlers/dynamic_routes/quick_menu.rs`：

```rust
use actix_web::{web, HttpResponse};
use crate::app_state::AppState;

/// 快捷菜单路由项
#[derive(Debug, Serialize)]
struct QuickMenuRoute {
    id: Option<i64>,
    name: String,
    path: String,
    icon: String,
    order: i32,
    group_id: Option<String>,
    group_name: Option<String>,
}

/// 获取快捷菜单路由列表
pub async fn get_quick_menu_routes(
    state: web::Data<AppState>,
) -> HttpResponse {
    let routes = if let Some(manager) = state.route_type_manager() {
        match manager.list_all_routes().await {
            Ok(routes) => routes,
            Err(e) => {
                return HttpResponse::InternalServerError().json(serde_json::json!({
                    "success": false,
                    "message": format!("查询失败: {}", e)
                }));
            }
        }
    } else {
        let repo = state.dynamic_route_repository();
        match repo.list(0, 10000, None, Some(true)).await {
            Ok((routes, _)) => routes,
            Err(e) => {
                return HttpResponse::InternalServerError().json(serde_json::json!({
                    "success": false,
                    "message": format!("查询失败: {}", e)
                }));
            }
        }
    };

    let mut quick_menu_routes = Vec::new();

    for route in routes.into_iter().filter(|r| r.enabled) {
        // 直接访问 group_id 和 is_primary_entry 字段
        let should_show = if let Some(group_id) = &route.group_id {
            // 如果有路由组，只显示主要入口
            route.is_primary_entry.unwrap_or(false)
        } else {
            // 如果没有路由组，使用原有的 metadata.show_in_quick_menu 字段
            route.metadata
                .as_ref()
                .and_then(|m| m.get("show_in_quick_menu"))
                .and_then(|v| v.as_bool())
                .unwrap_or(false)
        };

        if should_show {
            // 从 metadata 中提取辅助信息
            let metadata = route.metadata.as_ref();
            let icon = metadata
                .and_then(|m| m.get("menu_icon"))
                .and_then(|v| v.as_str())
                .unwrap_or("link")
                .to_string();
            let order = metadata
                .and_then(|m| m.get("menu_order"))
                .and_then(|v| v.as_i64())
                .unwrap_or(100) as i32;
            let group_name = metadata
                .and_then(|m| m.get("group_name"))
                .and_then(|v| v.as_str())
                .map(|s| s.to_string());

            quick_menu_routes.push(QuickMenuRoute {
                id: route.id,
                name: route.route_name.unwrap_or_else(|| route.path.clone()),
                path: route.path,
                icon,
                order,
                group_id: route.group_id,
                group_name,
            });
        }
    }

    // 按 order 排序
    quick_menu_routes.sort_by_key(|r| r.order);

    HttpResponse::Ok().json(serde_json::json!({
        "success": true,
        "data": {
            "routes": quick_menu_routes
        }
    }))
}
```

## 5. 优势和注意事项

### 5.1 优势

1. **职责单一**
   - `group_id` 和 `is_primary_entry` 作为独立字段，职责明确
   - `metadata` 只用于存储辅助信息（如图标、描述等）
   - 代码结构清晰，易于维护

2. **性能优化**
   - 避免了 JSON 解析开销
   - 数据库查询更高效（可以直接索引 group_id）
   - 前端访问更快（直接访问对象属性）

3. **简洁性**
   - 快捷菜单不再拥挤
   - 用户界面更加清晰

4. **易用性**
   - 管理员只需配置一次路由组
   - 不需要为每个路由单独设置

5. **扩展性**
   - 支持多个路由组
   - 可以扩展更多路由组功能

6. **向后兼容**
   - 不设置路由组的路由正常工作
   - 现有功能不受影响

### 5.2 注意事项

1. **唯一性约束**
   - 同一路由组应该只有一个主要入口
   - 需要在保存时验证

2. **数据一致性**
   - 删除主要入口时需要处理
   - 建议提示用户是否要删除整个路由组

3. **用户体验**
   - 用户需要知道如何访问相关路由
   - 主要入口页面应该提供清晰的导航

4. **数据库迁移**
   - 需要添加新的列到数据库
   - 确保迁移脚本的正确性

### 5.3 安全考虑

1. **输入验证**
   - 验证路由组 ID 格式
   - 限制路由组 ID 长度

2. **权限控制**
   - 只有管理员可以设置路由组
   - 防止未授权的路由分组

3. **XSS 防护**
   - 路由组名称需要转义
   - 防止恶意输入

## 7. 总结

本设计方案通过在 `DynamicRoute` 模型中添加独立字段，实现了"一组路由只显示主要入口"的需求：

1. **核心概念**：路由组（group_id）+ 主要入口（is_primary_entry）
2. **实现方式**：添加独立字段到模型，而不是使用 metadata
3. **职责单一**：`metadata` 只用于存储辅助信息，不存储业务逻辑字段
4. **性能优化**：避免 JSON 解析，提高查询性能
5. **向后兼容**：不设置路由组的路由保持原有行为
6. **易于使用**：管理员只需设置路由组 ID 和标记主要入口
7. **可扩展性**：metadata 中可以存储路由组名称、排序等辅助信息

该方案在保持现有功能不变的前提下，通过职责单一和性能优化，优雅地解决了快捷菜单拥挤的问题，提升了用户体验。
