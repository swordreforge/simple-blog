# Rustblog 包体优化建议

## 📊 当前包体情况

- **Release 二进制文件**: 6.4M (已使用 UPX 压缩, musl target)
- **Debug 二进制文件**: 33M
- **静态资源 (static/dist/)**: 4.6M (外部,不嵌入二进制)

### 嵌入内容分析

**rust-embed 配置 (embedded.rs):**
```rust
#[derive(RustEmbed)]
#[folder = "."]
#[include = "templates/**"]  // 5.3M (64个文件)
#[include = "img/**"]       // 1.5M
#[include = "music/**"]     // 8.0K
#[exclude = "data/GeoLite2-City.mmdb"]
```

**嵌入大小分布:**
- `templates/`: 5.3M (主要贡献者)
- `img/`: 1.5M
- `music/`: 8.0K
- **总计嵌入**: ~6.8M

**最大模板文件:**
1. `templates/passage.html`: 152K
2. `templates/admin/admin.html`: 136K
3. `templates/collect.html`: 64K
4. `templates/index.html`: 40K

## 🎯 优化分析

根据 `unused-features` 工具分析,已经移除了 **122个未使用的依赖特性**。

**关键结论:** 由于必须嵌入模板文件以实现单二进制部署,**5.0M-6.4M 的二进制大小是合理的**。优化重点应放在:

1. 减少嵌入的静态资源大小
2. 优化模板文件内容
3. 精简依赖库

### 已移除的特性概览

**关键依赖优化:**
- `jsonwebtoken`: 移除 11 个未使用特性 (hmac, p384, pem, rand, ed25519-dalek 等)
- `tokio`: 移除 11 个未使用特性 (socket2, bytes, fs, libc 等)
- `tracing-subscriber`: 移除 14 个未使用特性 (tracing-serde, fmt, once_cell 等)
- `regex`: 移除 8 个未使用特性 (perf-backtrack, perf-dfa, perf-literal 等)
- `chrono`: 移除 7 个未使用特性 (now, iana-time-zone, winapi 等)
- `rusqlite`: 移除 4 个未使用特性 (bundled, modern_sqlite 等)

**加密相关优化:**
- `p256`: 移除 7 个特性
- `elliptic-curve`: 移除 5 个特性
- `ecdsa`: 移除 7 个特性

## 🔧 进一步优化建议

### 1. 依赖优化

#### a) 移除可选依赖 (预期减少 3-5%)

**当前配置:**
```toml
pprof = { version = "0.14", features = ["flamegraph", "criterion", "protobuf-codec"], optional = true }
simd-json = { version = "0.17", default-features = false, features = ["serde_impl"], optional = true }
```

**建议:**
- `pprof`: 性能分析功能,仅开发调试需要,生产环境应禁用
- `simd-json`: 性能提升有限(~5-10%),但会增加二进制体积

**操作:** 确保 `[features]` 中这些 feature 未在 default 中启用

#### b) 评估音频元数据库 (预期减少 2-3%)

**当前配置:**
```toml
id3 = { version = "0.6", default-features = false }
metaflac = { version = "0.2", default-features = false }
```

**检查项目:**
- 搜索代码中使用 `id3` 或 `metaflac` 的地方
- 如果音乐播放功能不需要显示 MP3/FLAC 元数据,可以移除

#### c) 评估 GeoIP 功能 (预期减少 1-2%)

**当前配置:**
```toml
maxminddb = "0.27.1"
memmap2 = "0.9"
```

**检查项目:**
- 搜索 `maxminddb` 使用情况
- 如果不需要 IP 地理位置分析功能,可以移除

#### d) 优化 regex 特性

**当前配置:**
```toml
regex = { version = "1.11", default-features = false, features = ["std", "perf"] }
```

**建议:** 如果不需要高级正则匹配性能优化:
```toml
regex = { version = "1.11", default-features = false, features = ["std"] }
```

### 2. 静态资源嵌入优化 (预期减少 10-15%)

**当前嵌入内容:**
- ✅ `templates/`: 5.3M - **必须嵌入** (核心功能)
- ⚠️  `img/`: 1.5M - **可优化**
- ✅ `music/`: 8.0K - 很小,无需优化

#### a) 图片优化 (预期减少 0.5-0.8M)

**当前图片:**
```bash
img/
├── avatar.webp
├── mobile-test.webp
├── passage-cover.webp
├── passage-cover2.webp
├── police.png
└── test.webp
```

**优化方案:**
1. **PNG 转 WebP:**
   ```bash
   cwebp -q 80 police.png -o police.webp
   # 预期: police.png (~100K) → police.webp (~20K)
   ```

2. **进一步压缩 WebP:**
   ```bash
   cwebp -q 75 -m 6 input.webp -o output.webp
   # 预期: 减少 20-30%
   ```

3. **移除测试图片:**
   - `mobile-test.webp` - 如果仅用于测试,可以移除
   - `test.webp` - 同上

#### b) 模板内联资源优化 (预期减少 0.3-0.5M)

**问题:** 模板文件中内联了 CSS/JS,增加了模板大小

**优化方案:**
1. **将内联 JS 提取到独立文件:**
   ```html
   <!-- 检查 passage.html 中的内联脚本 -->
   <script>
       // 大量内联代码...
   </script>
   ```

2. **压缩内联内容:**
   - 已压缩的文件保持现状
   - 检查是否有未压缩的内联代码

#### c) 移除未使用的模板文件 (预期减少 0.1-0.2M)

**检查清单:**
```bash
# 查找可能未使用的模板
grep -r "keyboard-test" templates/ src/
grep -r "status/405.html" templates/ src/
```

**可能可移除:**
- `templates/keyboard-test.html` (如果仅用于测试)
- 部分状态页面 (如果可以动态生成)

### 4. 编译配置优化

#### a) 启用 Strip 符号表

**在 Cargo.toml 中添加:**
```toml
[profile.release]
strip = true  # 移除符号表
```

**预期效果:** 减少约 5-10% (压缩前),UPX 压缩后效果较小

#### b) 优化编译选项

**当前配置:**
```toml
[profile.release]
opt-level = 3
lto = "fat"
codegen-units = 1
panic = "abort"
```

**建议优化:**
```toml
[profile.release]
opt-level = "z"  # 优化体积而非速度
lto = "fat"
codegen-units = 1
panic = "abort"
strip = true
overflow-checks = false
debug = false
debug-assertions = false
incremental = false
```

**预期效果:**
- `opt-level = "z"` 可能减少 10-15%
- 但可能影响性能约 5-10%

#### c) 构建目标优化

**当前:**
```bash
cargo build --release --target x86_64-unknown-linux-musl
```

**优化:**
```bash
RUSTFLAGS='-C target-feature=+crt-static -C link-arg=-s' \
cargo build --release --target x86_64-unknown-linux-musl
```

### 5. 代码级优化

#### a) 检查 unused-features 报告中的误删

**需要验证的关键依赖:**

1. **tokio 的 `io-util` 和 `sync` 被标记为未使用**
   - 这些是异步 I/O 和同步原语的基础
   - 如果误删,需要重新添加

2. **serde 的 `derive` 和 `std` 被标记为未使用**
   - 如果代码中使用 `#[derive(Serialize, Deserialize)]`,需要保留
   - 检查所有结构体定义

3. **regex 的 `perf` 特性被移除**
   - 可能影响正则表达式性能
   - 根据实际使用情况决定是否回退

**验证方法:**
```bash
# 完整构建检查
cargo build --release

# 运行测试确保功能正常
cargo test --release
```

#### b) 减少 panic 相关代码

**当前:**
```toml
panic = "abort"
```

**补充:**
- 检查代码中的 `unwrap()` 和 `expect()` 调用
- 替换为 `?` 操作符或显式错误处理
- 可以减少 panic 相关的代码

### 6. 部署优化

#### a) 分离静态资源

**当前:**
- 所有文件在单个二进制中

**建议:**
```
部署结构:
rustblog (6.4M)
├── templates/ (可选)
└── static/ (4.6M)
```

**优点:**
- 更新静态资源无需重新编译
- 可以使用 CDN 加速静态资源
- 二进制体积更小

#### b) 使用 Docker 多阶段构建

```dockerfile
# 构建阶段
FROM rust:1.83 as builder
WORKDIR /app
COPY . .
RUN cargo build --release --target x86_64-unknown-linux-musl

# 运行阶段
FROM alpine:latest
COPY --from=builder /app/target/x86_64-unknown-linux-musl/release/rustblog /usr/local/bin/
COPY templates/ /app/templates/
COPY static/ /app/static/
CMD ["rustblog"]
```

## ⚠️ 注意事项

1. **单二进制架构限制**
   - 必须嵌入 `templates/` (5.3M) 以实现单文件部署
   - 当前 6.4M 是合理的大小范围
   - 进一步优化空间有限

2. **性能 vs 体积平衡**
   - ⚠️  不建议使用 `opt-level = "z"` (影响性能)
   - 当前 `opt-level = 3` 是最优选择
   - UPX 压缩已足够

3. **兼容性测试**
   - 任何修改后必须完整测试:
     - 模板渲染功能
     - 静态资源加载
     - 图片显示
     - 管理后台功能

4. **部署流程**
   - 保持单二进制部署方式
   - `static/dist/` 作为外部资源
   - 确保文件结构正确

5. **回退方案**
   - Git 标记当前版本: `v1.1.4`
   - 保留优化前的 `Cargo.toml` 备份
   - 每次优化后进行完整测试
