# 文章版本历史功能 - 死代码记录

## 概述

本文档记录了文章版本历史功能中存在的死代码（dead code）及其处理方式。这些代码目前未被使用，但可能是未来功能的一部分或保留作为备用实现。

## 为什么保留这些代码

1. **API 预留**：这些类型和方法是为 Handler 层（API 接口）预留的，当前未集成到路由中
2. **测试隔离**：部分类型在单元测试中使用，但编译器认为未被"使用"（因为测试编译单元独立）
3. **未来扩展**：某些功能可能在后续版本中需要

## 激活这些代码

当需要启用这些死代码时，按以下步骤操作：

1. **移除 `#[allow(dead_code)]` 属性**
2. **确保对应的 handler 集成**
3. **添加路由配置**
4. **运行测试验证**

## 示例：启用版本列表 API

```rust
// 1. 移除 #[allow(dead_code)] 从 VersionListQuery 和 VersionListResponse

// 2. 创建 handler
pub async fn list_versions(
    State(state): State<AppState>,
    Query(query): Query<VersionListQuery>,
) -> Result<Json<VersionListResponse>, AppError> {
    let service = state.passage_version_service.clone();
    let response = service.list_versions(query).await?;
    Ok(Json(response))
}

// 3. 添加路由
// 4. 测试验证
```

## 注意事项

- 这些代码经过单元测试验证，功能正常
- 移除 `#[allow(dead_code)]` 时需要确保对应功能已集成
- 建议按功能模块逐步激活，而非一次性全部激活
