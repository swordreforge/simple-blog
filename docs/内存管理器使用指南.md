# 内存管理器使用指南

本指南介绍如何为 RustBlog 项目配置和使用不同的内存管理器来优化性能和减少内存碎片。

## 支持的内存管理器

### 1. jemalloc (推荐用于高并发场景)

**特点：**
- 高性能多线程分配器
- 专为高并发应用优化
- 内存碎片化程度低
- 支持详细的内存统计

**适用场景：**
- 高并发 Web 服务器
- 需要精细内存管理的大型应用
- 长期运行的服务

**使用方法：**
```bash
# 使用 jemalloc 编译
cargo build --release --features jemalloc

# 运行应用
./target/release/rustblog
```

**性能特点：**
- 多线程分配性能优异
- 内存碎片少，适合长期运行
- 支持后台线程自动清理

### 2. mimalloc (推荐用于低内存使用)

**特点：**
- 微软开发的高性能分配器
- 内存使用效率高
- 分配速度快
- 适合内存受限环境

**适用场景：**
- 容器化部署
- 内存受限的服务器
- 需要低内存占用的应用

**使用方法：**
```bash
# 使用 mimalloc 编译
cargo build --release --features mimalloc-alloc

# 运行应用
./target/release/rustblog
```

**性能特点：**
- 内存使用效率高
- 分配速度快
- 适合长期运行服务

### 3. tcmalloc (备选方案)

**特点：**
- Google 开发的分配器
- 大规模多线程应用优化
- 成熟稳定

**适用场景：**
- 大规模分布式系统
- 需要稳定可靠的分配器
- Google 技术栈环境

**使用方法：**
```bash
# 使用 tcmalloc 编译
cargo build --release --features tcmalloc-alloc

# 运行应用
./target/release/rustblog
```

### 4. 系统默认分配器

**特点：**
- 无额外依赖
- 开发和测试使用
- 简单可靠

**适用场景：**
- 开发环境
- 小规模应用
- 不需要特殊优化的场景

**使用方法：**
```bash
# 使用系统默认分配器
cargo build --release

# 运行应用
./target/release/rustblog
```

```bash
cargo build
```

```bash
# 使用 jemalloc，多线程性能最佳
cargo build --release --features jemalloc
```

### 生产环境 - 容器化部署
```bash
# 使用 mimalloc，内存使用效率高
```

### 生产环境 - 追求稳定
```bash
# 使用 tcmalloc，成熟稳定
cargo build --release --features tcmalloc-alloc
```

## 环境变量配置

### jemalloc 配置
```bash
# 设置 jemalloc 参数
export MALLOC_CONF="background_thread:true,dirty_decay_ms:1000,muzzy_decay_ms:1000,narenas:4,lg_tcache_max:15"

# 运行应用
./target/release/rustblog
```

### mimalloc 配置
```bash
# 设置 mimalloc 参数
export MIMALLOC_SEGMENT_CACHE_ENABLED=1
export MIMALLOC_PAGE_RESET=0
export MIMALLOC_LARGE_OS_PAGES=1

# 运行应用
./target/release/rustblog
```

### tcmalloc 配置
```bash
# 设置 tcmalloc 参数
export TCMALLOC_MAX_TOTAL_THREAD_CACHE_BYTES=16777216
export TCMALLOC_AGGRESSIVE_DECOMMIT=true

# 运行应用
./target/release/rustblog
```

## 性能监控

### 查看当前分配器
启动应用时会显示当前使用的内存管理器：
```
🧠 内存管理器:
   - 类型: jemalloc
   - 描述: 高性能多线程分配器，适合高并发场景，内存碎片少
```

### 监控内存使用 (jemalloc)
jemalloc 支持详细的内存统计，可以集成到监控系统中：
```rust
// 在代码中获取内存统计
if let Some(_stats) = allocator::get_memory_stats() {
    // 处理统计信息
}
```

## 故障排除

### 问题：编译失败
```bash
# 确保使用最新的 Rust 版本
rustup update

# 清理并重新编译
cargo clean
cargo build --release --features jemalloc
```

### 问题：运行时错误
```bash
# 检查系统兼容性
# jemalloc 和 mimalloc 在某些平台上可能有限制

# 回退到系统默认分配器
cargo build --release
```

### 问题：内存占用增加
```bash
# 调整分配器参数
# 对于 jemalloc，增加清理频率
export MALLOC_CONF="dirty_decay_ms:500,muzzy_decay_ms:500"

# 对于 mimalloc，启用页面重置
export MIMALLOC_PAGE_RESET=1
```

## 最佳实践

1. **开发阶段**：使用系统默认分配器，编译速度快
2. **测试阶段**：测试不同的分配器，选择最适合的
3. **生产部署**：根据实际负载选择分配器
4. **监控**：持续监控内存使用和性能指标
5. **调优**：根据监控结果调整分配器参数

## 总结

选择合适的内存管理器可以显著提升 RustBlog 的性能：

- **高并发场景**：推荐 jemalloc
- **内存受限**：推荐 mimalloc
- **追求稳定**：推荐 tcmalloc
- **快速开发**：使用系统默认

建议在生产环境中使用专门的内存管理器，并根据实际监控数据进行调优。
