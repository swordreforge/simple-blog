### 1. 后端集成

#### 1.1 创建 Handler 层
**文件**：`src/handlers/api_handlers/passage/version.rs`

**需要实现的 API 端点**：

| 方法 | 路径 | 功能 | Handler 函数 |
|------|------|------|--------------|
| GET | `/api/admin/passages/{uuid}/versions` | 获取版本列表 | `list_versions` |

- 参数验证和清洗

#### 1.2 配置 API 路由
**文件**：`src/routes/api_routes.rs`

**需要添加的路由配置**：

```rust
// 文章版本历史管理路由
web::scope("/api/admin/passages/{uuid}")
    .service(

        web::resource("/versions/{version_number}")

    )
    .service(
        web::resource("/versions/diff")
            .route(web::get().to(api_handlers::passage::version::diff_versions))
    )
    .service(
        web::resource("/versions/{version_number}/restore")
            .route(web::post().to(api_handlers::passage::version::restore_version))
    )
    .service(
        web::resource("/versions/undo")
            .route(web::post().to(api_handlers::passage::version::undo))
    )
    .service(
        web::resource("/versions/redo")
            .route(web::post().to(api_handlers::passage::version::redo))
    );
```

#### 1.3 集成自动保存
**文件**：`src/handlers/api_handlers/passage/crud.rs`

**修改位置**：`update_passage()` 函数

**集成步骤**：
1. 在文章更新成功后，检查配置是否启用历史版本
2. 如果启用，调用 `PassageVersionService::auto_save_version()`
3. 捕获并记录保存失败的情况（不影响文章更新）

**示例代码**：

```rust
// 更新文章后
if let Err(e) = version_service.auto_save_version(
    passage.id,
    passage.uuid.clone(),
    &old_passage,
    &new_passage,
    change_reason
).await {
    log::warn!("自动保存文章历史版本失败: {}", e);
}
```

## ⚠️ 注意事项

### 1. 权限控制

所有版本管理 API 都需要管理员权限验证：

```rust
// 示例：在 Handler 中验证权限
pub async fn list_versions(
    uuid: web::Path<String>,
    req: HttpRequest,
    db_pool: web::Data<Pool<SqliteConnectionManager>>,
) -> Result<HttpResponse, Error> {
    // 验证 JWT token
    let claims = extract_jwt_claims(&req)?;

    // 验证管理员权限
    if claims.role != "admin" {
        return Ok(HttpResponse::Forbidden().json(json!({
            "error": "需要管理员权限"
        })));
    }

    // 继续处理...
}
```

### 2. 并发安全

**已知问题**（详见 `docs/技术债务/文章版本历史功能-死锁与数据竞争排查.md`）：

1. **恢复操作风险高** - 多步骤操作需要事务保护
2. **缓存击穿** - 并发请求可能导致缓存覆盖
3. **版本号生成** - 需要互斥保护

**建议修复**：

```rust
// 使用互斥锁保护关键操作
use tokio::sync::Mutex;

static VERSION_LOCK: Mutex<()> = Mutex::const_new(());

pub async fn restore_version(...) {
    let _guard = VERSION_LOCK.lock().await;
    // 执行恢复操作
}
```

### 3. 错误处理

所有 API 应返回统一的错误格式：

```rust
{
    "success": false,
    "error": "错误消息",
    "code": "ERROR_CODE"
}
```

### 4. 日志记录

关键操作需要记录日志：

```rust
log::info!("用户 {} 恢复文章 {} 到版本 {}", user_id, uuid, version_number);
log::warn!("自动保存版本失败: {}", error);
```

### 5. 缓存失效

版本相关操作后需要清除缓存：

```rust
// 清除版本列表缓存
cache.invalidate(&format!("versions:{}", uuid));

// 清除最新版本缓存
cache.invalidate(&format!("latest_version:{}", uuid));
```

### 6. 数据库事务

恢复和删除操作应该使用事务：

```rust
let mut conn = pool.get()?;
let tx = conn.transaction()?;

// 执行操作
tx.execute("UPDATE passages SET ...", [])?;
tx.execute("INSERT INTO passage_versions ...", [])?;

tx.commit()?;
```
