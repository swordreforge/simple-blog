# 路由迁移逻辑完善方案

## 1. 当前问题分析

### 1.1 已发现的问题

1. **批量迁移缺少类型过滤**
   - 问题：`migrate_all_routes` 使用 `from_storage.list_routes()` 获取路由列表
   - 原因：`DynamicRouteRepository::list_routes()` 返回所有路由，不管 route_type
   - 后果：批量迁移会尝试迁移所有路由，而不是只迁移指定类型的路由

2. **批量迁移缺少错误日志**
   - 问题：迁移失败时只是不增加计数，不记录错误原因
   - 后果：无法诊断迁移失败的原因

3. **导入 file 类型路由时模板文件缺失**
   - 问题：导入时只保存路由配置，不创建 template_path 文件
   - 后果：file 类型路由无法正常工作

4. **导入 file 类型路由后 inline_template 未清除**
   - 问题：文件内容写入后，数据库中仍保留 inline_template
   - 后果：file 类型路由应该 inline_template 为空

5. **导出 file 类型路由时缺少模板内容**
   - 问题：导出的配置文件中 inline_template 为空
   - 后果：导出的配置不完整，导入时缺少模板内容

### 1.2 架构设计理解

根据《路由存储管理API架构说明.md》：

**核心设计理念**：
1. **数据库作为中心存储和中转站**
   - 所有路由配置都存储在数据库中
   - 数据库既是持久化存储，也是路由配置的中转站

2. **route_type 表示运行时行为，而非存储位置**
   - `database`: 每次请求都从数据库查询路由配置（实时性高，性能较低）
   - `memory`: 启动时从数据库加载到内存，后续从内存读取（性能高，启动时加载）
   - `file`: 从配置文件读取路由配置（便于版本控制和编辑）

3. **存储统计的正确性**
   - 按 `route_type` 分类统计路由数量是正确的
   - 这反映了不同运行时类型的路由分布

**路由加载流程**：
```
启动时
  ↓
从数据库查询所有路由配置
  ↓
根据 route_type 分类：
  - database: 标记为需要实时查询
  - memory: 加载到内存存储
  - file: 记录配置文件路径
  ↓
加载到路由表
```

## 2. 迁移逻辑完善方案

### 2.1 迁移分类

根据架构设计，迁移可以分为三类：

#### 2.1.1 文件 ↔ 数据库/内存（涉及 IO 读写）

**特点**：
- 涉及文件 IO 操作
- 需要字段转换：`template_path` ↔ `inline_template`
- 迁移到文件类型时，需要删除旧的 inline_template
- 迁移出文件类型时，需要考虑是否删除模板文件

**迁移流程**：

**File → Database/Memory**：
```
1. 从数据库加载路由配置
2. 读取 template_path 指定的文件内容
3. 将内容设置到 inline_template
4. 清除 template_path 字段
5. 更新 route_type
6. 更新数据库记录
7. 如果是 memory 类型，加载到内存存储
```

**Database/Memory → File**：
```
1. 从数据库加载路由配置
2. 确定模板文件路径（使用 template_path 或生成默认路径）
3. 确保目录存在
4. 将 inline_template 内容写入文件
5. 清除 inline_template 字段
6. 设置 template_path
7. 更新 route_type
8. 更新数据库记录
9. 如果是从 memory 迁移，从内存存储删除
```

#### 2.1.2 数据库 ↔ 内存（仅后端切换）

**特点**：
- 不涉及字段转换
- 两者都使用 inline_template
- 只需要切换运行时后端

**迁移流程**：

**Database → Memory**：
```
1. 从数据库加载路由配置
2. 更新 route_type 为 Memory
3. 更新数据库记录
4. 加载到内存存储
5. 清除数据库中的 inline_template（可选，根据性能需求）
```

**Memory → Database**：
```
1. 从内存存储加载路由配置
2. 更新 route_type 为 Database
3. 更新数据库记录
4. 从内存存储删除
```

### 2.2 完善的迁移逻辑

#### 2.2.1 单个路由迁移

```rust
pub async fn migrate_route(
    &self,
    id: i64,
    from_type: RouteType,
    to_type: RouteType,
) -> Result<(), StorageError> {
    // 1. 参数验证
    if from_type == to_type {
        return Err(StorageError::InvalidData(
            "Source and destination types are the same".to_string(),
        ));
    }

    // 2. 从数据库加载路由配置（所有路由都在数据库中）
    let mut route = self.database_storage
        .get_by_id(id)
        .await
        .map_err(|e| StorageError::DatabaseError(format!("Failed to load route: {}", e)))?
        .ok_or_else(|| StorageError::NotFound(format!("Route {} not found", id)))?;

    // 3. 字段转换和 IO 操作
    match (from_type, to_type) {
        // File -> Database/Memory: 读取文件内容到 inline_template
        (RouteType::File, RouteType::Database) |
        (RouteType::File, RouteType::Memory) => {
            let template_path = route.template_path.as_ref()
                .ok_or_else(|| StorageError::InvalidData(
                    "File type route missing template_path".to_string()
                ))?;

            // 读取模板文件
            let content = std::fs::read_to_string(template_path)
                .map_err(|e| StorageError::FileError(
                    format!("Failed to read template file {}: {}", template_path, e)
                ))?;

            // 设置 inline_template
            route.inline_template = Some(content);
            // 清除 template_path
            route.template_path = None;

            tracing::info!("迁移路由 {}: 读取文件 {} 内容到 inline_template", id, template_path);

            // 可选：删除模板文件（建议保留作为备份）
            // let _ = std::fs::remove_file(template_path);
        }

        // Database/Memory -> File: 将 inline_template 写入文件
        (RouteType::Database, RouteType::File) |
        (RouteType::Memory, RouteType::File) => {
            let inline_template = route.inline_template.as_ref()
                .ok_or_else(|| StorageError::InvalidData(
                    "Cannot migrate route without inline_template to file type".to_string()
                ))?;

            // 确定文件路径
            let template_path = route.template_path.clone()
                .unwrap_or_else(|| format!("data/routes/routes/route_{}.html", route.id.unwrap_or(0)));

            // 确保目录存在
            if let Some(parent_dir) = std::path::Path::new(&template_path).parent() {
                std::fs::create_dir_all(parent_dir)
                    .map_err(|e| StorageError::FileError(
                        format!("Failed to create directory {}: {}", parent_dir.display(), e)
                    ))?;
            }

            // 写入文件
            std::fs::write(&template_path, inline_template)
                .map_err(|e| StorageError::FileError(
                    format!("Failed to write template file {}: {}", template_path, e)
                ))?;

            // 设置 template_path
            route.template_path = Some(template_path);
            // 清除 inline_template
            route.inline_template = None;

            tracing::info!("迁移路由 {}: 将 inline_template 写入文件 {}", id, route.template_path.as_ref().unwrap());
        }

        // Database <-> Memory: 直接迁移，无需字段转换
        (RouteType::Database, RouteType::Memory) |
        (RouteType::Memory, RouteType::Database) => {
            tracing::info!("迁移路由 {}: database <-> memory 无需字段转换", id);
        }

        _ => {
            return Err(StorageError::InvalidData(
                format!("Unsupported migration: {:?} -> {:?}", from_type, to_type)
            ));
        }
    }

    // 4. 更新路由类型
    route.route_type = to_type;
    route.updated_at = chrono::Utc::now();

    // 5. 更新数据库记录
    self.database_storage.update(id, &route).await
        .map_err(|e| StorageError::DatabaseError(format!("Failed to update route: {}", e)))?;

    // 6. 更新存储后端
    // 如果迁移到 memory，加载到内存存储
    if to_type == RouteType::Memory {
        let memory_storage = self.get_storage(&RouteType::Memory);
        memory_storage.save_route(&route).await?;
        tracing::info!("迁移路由 {}: 已加载到内存存储", id);
    }

    // 如果从 memory 迁移走，从内存存储删除
    if from_type == RouteType::Memory {
        let memory_storage = self.get_storage(&RouteType::Memory);
        memory_storage.delete_route(id).await?;
        tracing::info!("迁移路由 {}: 已从内存存储删除", id);
    }

    // 如果迁移到 file，保存到文件存储
    if to_type == RouteType::File {
        let file_storage = self.get_storage(&RouteType::File);
        file_storage.save_route(&route).await?;
        tracing::info!("迁移路由 {}: 已保存到文件存储", id);
    }

    // 如果从 file 迁移走，从文件存储删除
    if from_type == RouteType::File {
        let file_storage = self.get_storage(&RouteType::File);
        file_storage.delete_route(id).await?;
        tracing::info!("迁移路由 {}: 已从文件存储删除", id);
    }

    tracing::info!("成功迁移路由 {} 从 {:?} 到 {:?}", id, from_type, to_type);

    Ok(())
}
```

#### 2.2.2 批量路由迁移

```rust
pub async fn migrate_all_routes(
    &self,
    from_type: RouteType,
    to_type: RouteType,
) -> Result<usize, StorageError> {
    // 1. 参数验证
    if from_type == to_type {
        return Err(StorageError::InvalidData(
            "Source and destination types are the same".to_string(),
        ));
    }

    // 2. 从数据库中按类型查询路由
    // 注意：所有路由都存储在数据库中，route_type 表示运行时行为
    let routes = self.database_storage
        .list(0, 10000, Some(from_type), None)
        .await
        .map_err(|e| StorageError::DatabaseError(format!("Failed to list routes: {}", e)))?
        .0;

    tracing::info!("准备迁移 {} 条路由，从 {:?} 到 {:?}", routes.len(), from_type, to_type);

    let mut migrated_count = 0;
    let mut failed_count = 0;
    let mut failed_routes: Vec<(i64, String)> = Vec::new();

    // 3. 逐个迁移
    for route in routes {
        let id = route.id.ok_or_else(|| {
            StorageError::InvalidData("Route ID is required for migration".to_string())
        })?;

        match self.migrate_route(id, from_type, to_type).await {
            Ok(_) => {
                migrated_count += 1;
                tracing::debug!("路由 {} 迁移成功", id);
            }
            Err(e) => {
                failed_count += 1;
                let error_msg = e.to_string();
                tracing::error!("迁移路由 {} 失败: {}", id, error_msg);
                failed_routes.push((id, error_msg));
            }
        }
    }

    // 4. 输出迁移结果
    tracing::info!(
        "批量迁移完成: 源类型={:?}, 目标类型={:?}, 成功={}, 失败={}",
        from_type, to_type, migrated_count, failed_count
    );

    if !failed_routes.is_empty() {
        tracing::warn!("失败的路由: {:?}", failed_routes);
    }

    Ok(migrated_count)
}
```

#### 2.3.3 并发控制

**问题**：
- 批量迁移时可能影响正在运行的路由
- 需要考虑并发访问问题

**解决方案**：
- 使用锁机制保护共享资源
- 迁移时标记路由为"迁移中"状态
- 迁移完成后热更新路由表

### 2.4 导入导出完善

#### 2.4.1 导出时的特殊处理

```rust
pub async fn export_routes(
    state: web::Data<AppState>,
) -> Result<ExportData, StorageError> {
    let repo = state.dynamic_route_repository();

    // 1. 获取所有路由
    let mut routes = repo.list(0, 10000, None, None).await?.0;

    // 2. 对 file 类型的路由进行特殊处理
    for route in &mut routes {
        if route.route_type == RouteType::File {
            if let Some(ref template_path) = route.template_path {
                // 读取模板文件内容
                match std::fs::read_to_string(template_path) {
                    Ok(content) => {
                        tracing::info!("导出 file 类型路由: 已读取模板文件 {}", template_path);
                        // 将文件内容放到 inline_template 中
                        route.inline_template = Some(content);
                    }
                    Err(e) => {
                        tracing::warn!("导出 file 类型路由: 无法读取模板文件 {}: {}", template_path, e);
                        // 如果读取失败，inline_template 保持为 None
                    }
                }
            }
        }
    }

    // 3. 返回导出数据
    Ok(ExportData {
        version: "1.0".to_string(),
        exported_at: chrono::Utc::now().to_rfc3339(),
        total: routes.len(),
        routes,
    })
}
```

#### 2.4.2 导入时的特殊处理

```rust
pub async fn import_routes(
    state: web::Data<AppState>,
    import_data: ImportData,
) -> Result<ImportResult, StorageError> {
    let repo = state.dynamic_route_repository();
    let manager = state.route_type_manager();

    let mut imported_count = 0;
    let mut failed_count = 0;
    let mut errors = Vec::new();

    for (index, route_data) in import_data.routes.iter().enumerate() {
        // 1. 创建数据库记录
        let db_id = repo.create(route_data).await
            .map_err(|e| {
                errors.push(format!("第{}条路由（数据库）: {}", index + 1, e));
                e
            })?;

        // 2. 特殊处理不同类型
        match route_data.route_type {
            RouteType::File => {
                // 如果有 inline_template，写入文件
                if let Some(ref inline_template) = route_data.inline_template {
                    let template_path = route_data.template_path.clone()
                        .unwrap_or_else(|| format!("data/routes/routes/route_{}.html", db_id));

                    // 创建目录和文件
                    std::fs::create_dir_all(std::path::Path::new(&template_path).parent().unwrap())?;
                    std::fs::write(&template_path, inline_template)?;

                    // 清除 inline_template
                    let mut updated_route = route_data.clone();
                    updated_route.id = Some(db_id);
                    updated_route.inline_template = None;
                    updated_route.template_path = Some(template_path);

                    // 更新数据库
                    repo.update(db_id, &updated_route).await?;
                }
            }
            RouteType::Memory => {
                // 加载到内存存储
                let storage = manager.get_storage(&RouteType::Memory);
                let mut updated_route = route_data.clone();
                updated_route.id = Some(db_id);
                storage.save_route(&updated_route).await?;
            }
            RouteType::Database => {
                // 数据库类型无需额外处理
            }
        }

        imported_count += 1;
    }

    Ok(ImportResult {
        imported: imported_count,
        failed: failed_count,
        errors,
    })
}
```

## 6. 总结

### 6.1 核心原则

1. **数据库为中心**：所有路由配置最终都存储在数据库中
2. **类型语义清晰**：route_type 表示运行时行为，不是存储位置
3. **字段转换正确**：file 类型使用 template_path，其他类型使用 inline_template
4. **错误处理完善**：提供详细的错误信息和回滚机制
5. **性能考虑**：支持批量操作和并发处理

- 批量迁移的类型过滤

**P1（重要优化）**：
