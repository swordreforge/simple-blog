# 路由字段重构计划

## 背景

当前动态路由系统中存在字段概念混淆的问题：
- `route_type` 和 `content_source` 字段的用途不清晰
- API返回数据显示不一致（route_type为"memory"但实际存储在数据库中）

## 设计目标

### 字段职责划分

1. **`route_type` 字段**
   - **作用**：决定路由的存储和读取方式
   - **可选值**：
     - `database`: 从数据库读取路由配置
     - `memory`: 内存映射路由（启动时加载到内存）
     - `file`: 从配置文件读取路由
   - **目的**：提醒系统从哪里获取路由配置

2. **`content_source` 字段删除**
   - **原因**：与 `route_type` 职责重复
   - **处理方式**：删除该字段，统一使用 `route_type`

3. **`content_template` → `inline_template` 字段重构**
   - **新名称**：`inline_template`
   - **作用**：存储模板文件的实际内容（纯文本）
   - **存储位置**：数据库或内存中
   - **支持格式**：HTML、JS、CSS、SVG 等简单的非二进制文件
   - **使用场景**：当 `handler_config` 缺失或不需要复杂配置时，直接使用这里存储的模板内容
   - **示例值**：`"<html><body>Hello World</body></html>"` 或 `"console.log('Hello');"`

4. **新增 `template_path` 字段**
   - **作用**：存储相对于二进制文件的配置模板文件路径
   - **适用场景**：当 `route_type` 为 `file` 时，从这里读取模板文件
   - **示例值**：`templates/route-configs/custom-page.html`

## 实施计划

### 阶段一：数据修正

1. **修正现有路由的 `route_type` 字段**
   - 将当前 `route_type` 为 `"memory"` 的路由修正为 `"database"`
   - 确保数据库中的数据与实际存储方式一致

### 阶段二：数据库结构更新

1. **重命名字段**
   - 将 `content_template` 字段重命名为 `inline_template`
   - 删除 `content_source` 字段（与 route_type 重复）
   - 添加新字段 `template_path`
   - 更新数据库表结构

2. **添加字段约束**
   - 为 `template_path` 添加适当的约束（可选字段）
   - 为 `inline_template` 添加 TEXT 类型约束
   - 为 `route_type` 添加 CHECK 约束，确保值只能是 database/memory/file

### 阶段三：代码更新

1. **数据模型更新**
   - 修改 `DynamicRoute` 结构体，将 `content_source` 改为 `template_path`
   - 更新相关的序列化/反序列化逻辑

2. **API Handler 更新**
   - 更新创建路由的 handler
   - 更新更新路由的 handler
   - **添加字段组合验证逻辑**：
     ```rust
     // 验证规则：根据 route_type 确定应该使用的字段

     // database 类型：应该使用 inline_template
     if route_type == "database" {
         if template_path.is_some() {
             return Err("database 类型路由不支持 template_path 字段");
         }
     }

     // memory 类型：应该使用 inline_template
     if route_type == "memory" {
         if template_path.is_some() {
             return Err("memory 类型路由不支持 template_path 字段");
         }
     }

     // file 类型：必须使用 template_path
     if route_type == "file" {
         if inline_template.is_some() {
             return Err("file 类型路由不支持 inline_template 字段");
         }
         if template_path.is_none() {
             return Err("file 类型路由必须提供 template_path 字段");
         }
     }
     ```

3. **前端代码更新**
   - 更新显示逻辑，使用新的字段名称
   - 更新表单提交逻辑

4. **存储层更新**

## 字段组合规则

### 不同 route_type 的字段使用规范

| route_type | 必需字段 | 可选字段 | 禁止字段 | 说明 |
|-----------|---------|---------|---------|------|
| **database** | - | `inline_template`, `handler_config` | `template_path` | 模板内容直接存储在数据库中 |
| **memory** | - | `inline_template`, `handler_config` | `template_path` | 模板内容加载到内存中 |
| **file** | `template_path` | `handler_config` | `inline_template` | 模板内容从外部文件读取 |

### 字段验证逻辑

```rust
// 根据不同的 route_type 验证字段组合
match route_type {
    RouteType::Database | RouteType::Memory => {
        // database/memory 类型禁止使用 template_path
        if template_path.is_some() {
            return Err("database/memory 类型路由不支持 template_path 字段");
        }
    }
    RouteType::File => {
        // file 类型禁止使用 inline_template
        if inline_template.is_some() {
            return Err("file 类型路由不支持 inline_template 字段");
        }
        // file 类型必须提供 template_path
        if template_path.is_none() {
            return Err("file 类型路由必须提供 template_path 字段");
        }
    }
}
```

### 典型使用场景

1. **数据库存储的简单页面**
   - `route_type`: `database`
   - `handler_type`: `static`
   - `inline_template`: `"<html><body>Hello</body></html>"`
   - `content_type_hint`: `text/html`

2. **文件存储的复杂模板**
   - `route_type`: `file`
   - `handler_type`: `template`
   - `template_path`: `templates/admin/custom-page.html`

3. **重定向路由（不需要模板）**
   - `route_type`: `database`
   - `handler_type`: `redirect`
   - `handler_config`: `{"target": "/new-location", "status_code": 302}`

完成后，系统将具有：

### 新的字段设计

```
核心字段：
- route_type: database/memory/file (存储方式)
- handler_type: redirect/static/proxy/custom (处理方式)
- handler_config: 处理器配置（JSON，可选）
- inline_template: 内联模板内容（纯文本，当handler_config缺失时使用）
- template_path: 模板文件的相对路径（当route_type=file时使用）
```
