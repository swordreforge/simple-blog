# 动态路由存储类型真实实现计划

## 1. 问题分析

### 1.1 当前状态

| 存储类型 | 实现状态 | 实际使用情况 |
|---------|---------|------------|
| Database | ✅ 完整实现 | ✅ 正在使用 |
| Memory | ✅ 完整实现 | ❌ 未使用 |
| File | ✅ 完整实现 | ❌ 未使用 |

### 1.2 核心问题

**问题 1：路由加载逻辑单一**
```rust
// 当前实现（src/services/dynamic_route_service.rs）
pub async fn load_routes_from_db(&self) -> Result<(), Box<dyn std::error::Error>> {
    let routes = self.repository.get_all_enabled().await;  // 只从数据库加载
    // ...
}
```

**问题 2：RouteTypeManager 未集成**
- `RouteTypeManager` 被初始化但未被 `DynamicRouteService` 使用
- 路由表（`RouteTable`）只从数据库加载，不会从内存或文件存储加载

**问题 3：route_type 字段只是标签**
当前创建路由时：
- `route_type: "memory"` → 仍然存储在数据库中
- `route_type: "file"` → 仍然存储在数据库中
- `route_type` 字段仅作为分类标签，不影响实际存储位置

### 1.3 影响范围

- 内存路由存储：已实现但闲置，浪费内存资源
- 文件路由存储：已实现但闲置，无法实现真正的文件配置
- 路由迁移功能：API 存在但无法验证迁移后的路由是否正常工作
- 性能优化：无法利用内存存储的高性能特性

---

## 2. 实现目标

### 2.1 核心目标

1. **统一路由加载**：从所有存储类型（Database、Memory、File）加载路由到路由表
2. **正确存储路由**：根据 `route_type` 将路由存储到对应的后端
3. **支持路由迁移**：验证迁移后的路由可以正常工作
4. **性能优化**：内存存储路由优先加载，数据库路由其次，文件路由最后

### 2.2 非功能性要求

- 向后兼容：不影响现有的数据库路由
- 性能要求：路由加载时间不超过 500ms（1000 条路由）
- 可靠性要求：路由加载失败不影响其他存储类型的路由
- 可测试性：提供测试接口验证各存储类型

---

```rust
/// 从所有存储类型加载路由
pub async fn load_all_routes(&self) -> Result<LoadStats, Box<dyn std::error::Error>> {
    let mut stats = LoadStats::default();

    // 1. 从内存存储加载（最快）
    if let Some(manager) = &self.route_type_manager {
        match manager.load_all_routes_from_storage(RouteType::Memory).await {
            Ok(routes) => {
                for route in routes {
                    if route.enabled {
                        self.add_route_to_table(&route)?;
                        stats.memory_loaded += 1;
                    }
                }
            }
            Err(e) => {
                tracing::warn!("从内存存储加载路由失败: {}", e);
            }
        }

        // 2. 从文件存储加载
        match manager.load_all_routes_from_storage(RouteType::File).await {
            Ok(routes) => {
                for route in routes {
                    if route.enabled {
                        self.add_route_to_table(&route)?;
                        stats.file_loaded += 1;
                    }
                }
            }
            Err(e) => {
                tracing::warn!("从文件存储加载路由失败: {}", e);
            }
        }

        // 3. 从数据库存储加载
        match manager.load_all_routes_from_storage(RouteType::Database).await {
            Ok(routes) => {
                for route in routes {
                    if route.enabled {
                        self.add_route_to_table(&route)?;
                        stats.database_loaded += 1;
                    }
                }
            }
            Err(e) => {
                tracing::warn!("从数据库存储加载路由失败: {}", e);
            }
        }
    } else {
        // 兼容性：如果没有 RouteTypeManager，只从数据库加载
        return self.load_routes_from_db().await
            .map(|_| LoadStats {
                database_loaded: self.repository.get_all_enabled().await?.len(),
                ..Default::default()
            });
    }

    tracing::info!("路由加载统计: {:?}", stats);
    Ok(stats)
}
```

### 3.3 路由创建修改

**文件 5：src/handlers/api_handlers/dynamic_routes/mod.rs**

修改创建路由逻辑，根据 `route_type` 选择存储后端
```rust
pub async fn create_route(
    state: web::Data<AppState>,
    route: web::Json<DynamicRoute>,
) -> Result<HttpResponse> {
    let route_type = route.route_type.unwrap_or(RouteType::Database);

    if let Some(manager) = &state.route_type_manager {
        // 根据 route_type 选择存储后端
        let storage = manager.get_storage(&route_type);
        match storage.save_route(&route).await {
            Ok(id) => {
                // 将新路由添加到路由表
                if route.enabled {
                    if let Err(e) = state.dynamic_route_service.add_route_to_table(&route) {
                        tracing::warn!("添加路由到路由表失败: {}", e);
                    }
                }
                return Ok(HttpResponse::Created().json(serde_json::json!({
                    "success": true,
                    "id": id,
                    "route_type": route_type
                })));
            }
            Err(e) => {
                return Ok(HttpResponse::InternalServerError().json(serde_json::json!({
                    "error": "创建路由失败",
                    "message": e.to_string()
                })));
            }
        }
    }

    // 兼容性：如果没有 RouteTypeManager，只使用数据库
    // ... 原有逻辑
}
```

## 6. 风险和缓解措施

### 6.1 风险识别

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 内存存储数据丢失 | 高 | 中 | 实现持久化机制，定期同步到数据库 |
| 文件系统权限问题 | 中 | 中 | 启动时检查权限，提供清晰错误提示 |
| 路由迁移失败 | 中 | 低 | 实现事务性迁移，失败自动回滚 |
| 性能下降 | 中 | 低 | 性能测试，优化加载顺序 |
| 兼容性问题 | 高 | 低 | 保留原有 API，渐进式迁移 |

### 6.2 回滚计划

**方案 1：配置开关**
```toml
[route_storage]
enable_multi_storage = true  # 可关闭，回退到单存储模式
```

**方案 2：环境变量**
```bash
export ROUTE_STORAGE_MODE=single  # single | multi
```

**方案 3：代码回退**
- 保留原有 `load_routes_from_db()` 方法
- 通过配置控制使用哪个方法
