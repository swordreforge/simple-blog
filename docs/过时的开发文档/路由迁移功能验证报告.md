## 核心设计理念

### 1. 数据库为中心
所有路由配置最终都存储在数据库中，数据库既是持久化存储，也是路由配置的中转站。

### 2. 类型语义清晰
`route_type` 表示运行时行为，不是存储位置：
- `Database`: 每次请求都从数据库查询路由配置（实时性高，性能较低）
- `Memory`: 启动时从数据库加载到内存，后续从内存读取（性能高，启动时加载）
- `File`: 从配置文件读取路由配置（便于版本控制和编辑）

### 3. 字段转换正确
- `File` 类型使用 `template_path`
- `Database` 和 `Memory` 类型使用 `inline_template`
- 迁移时进行正确的字段转换

## 使用示例

### API 使用示例

#### 1. 迁移单个路由
```bash
POST /api/admin/dynamic-routes/storage/migrate
{
  "route_id": 1,
  "target_type": "memory"
}
```

#### 2. 批量迁移路由
```bash
POST /api/admin/dynamic-routes/storage/migrate-batch
{
  "source_type": "database",
  "target_type": "memory"
}
```

#### 3. 获取存储统计
```bash
GET /api/admin/dynamic-routes/storage/stats
```
