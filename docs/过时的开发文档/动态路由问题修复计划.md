# 动态路由问题修复计划

## 问题概述

当前动态路由实现在静态内容处理方面存在以下核心问题：

1. **静态内容只使用 handler_config.content，忽略 inline_template**
2. **file类型路由未正确使用 template_path 读取真实模板文件**
3. **database类型路由的 inline_template 字段被忽略**
4. **前端上传文件bug：文件内容未正确填充到 inline_template 输入框**

## 问题分析

### 问题1：静态内容处理逻辑缺陷

**位置**：`src/services/dynamic_route_service.rs:143-154`

**问题代码**：
```rust
HandlerType::Static => {
    // 处理静态内容路由
    if let Some(content) = route.handler_config.get("content") {
        let content_str = content.as_str().ok_or("content 必须是字符串")?;
        let content_type = route.handler_config
            .get("content_type")
            .and_then(|v| v.as_str())
            .unwrap_or("text/plain");

        let static_route = SimpleRoute::new(content_str.to_string(), content_type.to_string());
        self.route_table.insert(normalized_path, Box::new(static_route));
    }
}
```

**问题**：
- 只从 `handler_config` 中读取 `content` 字段
- 完全忽略 `inline_template` 字段
- 完全忽略 `template_path` 字段

### 问题2：file类型路由未使用template_path

**位置**：同上

**问题**：
- file类型的路由有 `template_path` 字段，但代码未使用它来读取文件
- 应该从 `template_path` 指定的相对路径读取模板文件

### 问题3：database类型路由的inline_template被忽略

**位置**：同上

**问题**：
- database/memory类型的路由有 `inline_template` 字段，但代码未使用它
- 应该优先使用 `inline_template` 字段的内容

### 问题4：测试逻辑也存在相同问题

**位置**：`src/handlers/api_handlers/dynamic_routes/test.rs:155-170`

**问题**：
- `preview_response` 函数也只使用 `content` 字段
- 没有检查 `inline_template` 字段

### 问题5：前端上传文件bug

**位置**：`templates/js/dyn-routing.js` 中的 `handleFileUpload` 函数

**问题代码**：
```javascript
document.getElementById("contentTemplate").value=e;  // 错误的ID
```

**正确ID**：
```html
<textarea id="inlineTemplate" rows="6" placeholder="输入纯文本内容（HTML/JS/CSS/SVG等）..."></textarea>
```

**问题**：
- JavaScript代码使用的ID是 `contentTemplate`
- HTML中实际的ID是 `inlineTemplate`
- 导致文件内容无法正确填充到输入框

## 修复计划

### 修复1：重构静态内容处理逻辑

**目标**：根据路由类型和字段优先级，正确选择内容来源

**优先级顺序**：
1. **file类型**：优先使用 `template_path` 读取文件
2. **database/memory类型**：优先使用 `inline_template`
3. **兼容性**：如果以上都不存在，从 `handler_config.content` 读取（但这个字段应该被废弃）

**修改文件**：`src/services/dynamic_route_service.rs`

**具体修改**：

```rust
HandlerType::Static => {
    // 处理静态内容路由
    let content_str = match route.route_type {
        // file 类型：从 template_path 读取文件
        crate::db::models::RouteType::File => {
            if let Some(ref path) = route.template_path {
                // 读取模板文件
                match std::fs::read_to_string(path) {
                    Ok(content) => content,
                    Err(e) => {
                        tracing::error!("读取模板文件失败: path={}, error={}", path, e);
                        return Err(format!("读取模板文件失败: {}", e).into());
                    }
                }
            } else {
                return Err("file 类型路由必须提供 template_path".into());
            }
        }
        // database/memory 类型：优先使用 inline_template
        crate::db::models::RouteType::Database | crate::db::models::RouteType::Memory => {
            if let Some(ref template) = route.inline_template {
                if !template.is_empty() {
                    template.clone()
                } else {
                    // 兼容性：如果 inline_template 为空，尝试从 handler_config.content 读取
                    route.handler_config.get("content")
                        .and_then(|v| v.as_str())
                        .ok_or("需要提供 inline_template 或 handler_config.content")?
                        .to_string()
                }
            } else {
                // 兼容性：如果 inline_template 不存在，尝试从 handler_config.content 读取
                route.handler_config.get("content")
                    .and_then(|v| v.as_str())
                    .ok_or("需要提供 inline_template 或 handler_config.content")?
                    .to_string()
            }
        }
    };

    let content_type = route.handler_config
        .get("content_type")
        .and_then(|v| v.as_str())
        .unwrap_or("text/html; charset=utf-8");

    let static_route = SimpleRoute::new(content_str, content_type.to_string());
    self.route_table.insert(normalized_path, Box::new(static_route));
}
```

### 修复2：修复测试逻辑

**目标**：让测试预览也支持正确的字段优先级

**修改文件**：`src/handlers/api_handlers/dynamic_routes/test.rs`

**具体修改**：在 `preview_response` 函数中添加对 `inline_template` 的支持

```rust
HandlerType::Static => {
    let content = route.handler_config.get("content")
        .and_then(|v| v.as_str())
        .unwrap_or("");
    let content_type = route.handler_config.get("content_type")
        .and_then(|v| v.as_str())
        .unwrap_or("text/plain; charset=utf-8");

    // 检查是否有 inline_template
    let actual_content = if let Some(ref inline) = route.inline_template {
        if !inline.is_empty() {
            inline
        } else {
            content
        }
    } else {
        content
    };

    serde_json::json!({
        "status_code": 200,
        "headers": {
            "Content-Type": content_type
        },
        "body": actual_content
    })
}
```

### 修复4：废弃content字段（可选）

**目标**：逐步废弃 `handler_config.content` 字段，统一使用 `inline_template`

**建议**：
1. 在文档中说明 `handler_config.content` 字段已废弃
2. 在创建路由时，如果检测到 `handler_config.content` 存在，自动将其内容迁移到 `inline_template`
3. 在未来的版本中，完全移除对 `content` 字段的兼容性支持

**修改文件**：`src/handlers/api_handlers/dynamic_routes/create.rs`

**具体修改**：在创建路由时自动迁移 content 到 inline_template

```rust
// 在创建路由之前，检查是否需要迁移 content 到 inline_template
let inline_template = if route.inline_template.is_none() || route.inline_template.as_ref().is_some_and(|s| s.is_empty()) {
    // 如果 inline_template 为空，尝试从 handler_config.content 迁移
    route.handler_config.get("content")
        .and_then(|v| v.as_str())
        .map(|s| s.to_string())
        .or(route.inline_template)
} else {
    route.inline_template
};

// 清理 handler_config 中的 content 字段（如果已迁移）
let handler_config = if inline_template.is_some() {
    let mut config = route.handler_config.clone();
    if let Some(obj) = config.as_object_mut() {
        obj.remove("content");
    }
    config
} else {
    route.handler_config.clone()
};
```

## 修复后端到端的流程

### file类型路由流程

1. 用户在前端创建路由，选择 `route_type: file` 和 `handler_type: static`
2. 用户填写 `template_path` 字段，例如：`templates/test.html`
3. 后端验证：file类型必须提供 `template_path`
4. 后端保存路由到文件存储
5. 路由加载时，从 `template_path` 读取文件内容
6. 返回文件内容给用户

### database/memory类型路由流程

1. 用户在前端创建路由，选择 `route_type: database/memory` 和 `handler_type: static`
2. 用户可以：
   - 上传文件（自动填充到 `inline_template`）
   - 或直接在 `inline_template` 输入框中输入内容
3. 后端保存路由到相应存储
4. 路由加载时，使用 `inline_template` 字段的内容
5. 返回内容给用户

## 兼容性考虑

### 向后兼容

为了确保向后兼容，我们暂时保留对 `handler_config.content` 字段的支持：

1. 如果 `inline_template` 为空或不存在的路由，继续从 `handler_config.content` 读取内容
2. 在日志中输出警告，提示用户迁移到 `inline_template`
3. 在文档中明确说明 `handler_config.content` 字段已废弃

### 迁移建议

对于现有的使用 `handler_config.content` 的路由，建议：

1. 通过API查询这些路由
2. 将 `handler_config.content` 的内容迁移到 `inline_template`
3. 从 `handler_config` 中移除 `content` 字段
4. 重新保存路由
