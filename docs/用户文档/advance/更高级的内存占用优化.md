# 更高级的内存占用优化

RustBlog 经过深度编译优化，在资源受限的环境中表现出色。本文档提供更高级的内存优化策略，帮助您进一步降低内存占用。

## 默认性能表现

在 2 核 2G 服务器上的默认表现：

| 指标 | 数值 |
|------|------|
| 启动时内存 | 约 17MB（峰值 17.2MB） |
| 运行时内存 | 约 25MB（长期运行稳定） |
| 峰值内存 | 约 156MB（4:00被脚本漏扫） |
| 任务数 | 7-8 个（系统限制 1974） |
| 启动 CPU | 约 796ms |
| 长期运行 CPU | 13 小时累计 25.758s |
| 编译后体积 | 约 5.1MB（纯静态链接 + UPX 压缩） |

## 编译优化选项

### 1. 使用 jemalloc 内存分配器

jemalloc 是 Facebook 开发的高性能内存分配器，在高并发场景下内存碎片更少。

**编译时启用**：
```bash
cargo build --release --features jemalloc
```

**适用场景**：
- 高并发 Web 服务
- 长期运行的服务
- 需要稳定内存占用的场景

**效果**：
- 减少内存碎片
- 提高内存分配效率
- 长期运行内存更稳定

### 2. 使用 mimalloc 内存分配器

mimalloc 是 Microsoft Research 开发的分配器，具有良好的扩展性和低内存开销。

**编译时启用**：
```bash
cargo build --release --features mimalloc-alloc
```

**适用场景**：
- 通用服务器应用
- 需要低延迟的场景
- 跨平台部署

**效果**：
- 更好的缓存利用率
- 减少内存占用峰值
- 提高吞吐量

**运行时配置（环境变量）**：

mimalloc 支持通过环境变量进一步优化内存使用：

```bash
# 设置更保守的内存管理策略
export MIMALLOC_PAGE_RESET=1          # 页面重置，回收未使用内存
export MIMALLOC_LARGE_OS_PAGES=1      # 使用大页面减少 TLB 缺失
export MIMALLOC_MAX_EXTENSIONS=8      # 限制扩展块数量
export MIMALLOC_EAGER_COMMIT=0        # 禁用急切提交

# 运行程序
./rustblog --enable-cache --cache-backend auto -r
```

**环境变量说明**：
- `MIMALLOC_PAGE_RESET` - 重置未使用的页面以释放内存
- `MIMALLOC_LARGE_OS_PAGES` - 使用大页面减少内存开销
- `MIMALLOC_MAX_EXTENSIONS` - 限制扩展块数量，控制内存增长
- `MIMALLOC_EAGER_COMMIT` - 禁用急切提交，按需分配内存

**效果**：
- 额外降低 10-20% 内存占用
- 更好的内存回收能力
- 减少内存占用峰值

### 8. 使用 32 位编译

编译为 32 位程序可以显著降低内存占用，因为指针和基本数据类型的尺寸减半。

**编译为 32 位**：
```bash
# Linux x86_32
cargo build --release --target i686-unknown-linux-gnu

# 或使用 musl（静态链接）
cargo build --release --target i686-unknown-linux-musl
```

**添加目标架构**（首次使用时）：
```bash
# 添加 i686-unknown-linux-gnu 目标
rustup target add i686-unknown-linux-gnu

# 添加 i686-unknown-linux-musl 目标
rustup target add i686-unknown-linux-musl
```

**适用场景**：
- 内存极其受限的环境（< 512MB）
- 32 位 VPS
- 嵌入式设备
- 不需要大内存寻址的应用

**效果**：
- 内存占用降低 30-40%
- 指针大小：8 字节 → 4 字节
- 二进制文件体积减小
- 更好的缓存利用率

**注意事项**：
- 最大内存限制：约 4GB
- 需要安装 32 位库支持
- 性能可能略有下降（取决于 CPU）
- 某些依赖可能不支持 32 位

**系统依赖**（Ubuntu/Debian）：
```bash
# 安装 32 位编译工具链
sudo apt-get install gcc-multilib g++-multilib

# 安装 32 位运行时库
sudo apt-get install libc6:i386 libssl1.1:i386
```

**完整编译示例**：
```bash
# 1. 添加目标架构
rustup target add i686-unknown-linux-musl

# 2. 编译为 32 位（使用 musl 静态链接）
cargo build --release --target i686-unknown-linux-musl --features "mimalloc-alloc,compressed-embed"

# 3. 生成的二进制文件位于
# target/i686-unknown-linux-musl/release/rustblog
```

## 运行时优化

### 1. 启用缓存

缓存可以显著减少内存占用和 CPU 使用。

**启动参数**：
```bash
./rustblog --enable-cache --cache-backend auto -r
```

**缓存后端选择**：
- `auto` - 自动选择最优方案（推荐）
- `local` - 本地内存缓存
- `valkey` - Valkey/Redis 缓存

### 2. 使用只读模式

如果不需要写入操作，可以使用只读模式进一步降低内存占用。

**启动参数**：
```bash
./rustblog -r
```

**适用场景**：
- 静态博客
- 只读展示
- 降低安全风险

### 3. 限制并发连接

限制并发连接数可以控制内存峰值。

**启动参数**：
```bash
./rustblog --workers 2 --max-connections 1000
```

**参数说明**：
- `--workers` - 工作线程数（默认：CPU 核心数）
- `--max-connections` - 最大连接数

### 4. 调整日志级别

降低日志级别可以减少内存占用和 I/O 开销。

**启动参数**：
```bash
./rustblog --log-level warn
```

**日志级别**：
- `error` - 仅错误
- `warn` - 警告及以上（推荐）
- `info` - 信息及以上
- `debug` - 调试信息
- `trace` - 详细跟踪

## 系统优化

### 1. 使用网关防护（推荐）

在博客服务前面部署网关可以显著减少恶意流量对内存的影响，通过在网关层过滤和拦截恶意请求，可以有效降低内存峰值占用。

#### 网关防护的好处

- **减少无效请求** - 拦截恶意爬虫和扫描器，减少不必要的资源消耗
- **降低内存峰值** - 防止恶意流量导致内存突然飙升
- **提高安全性** - 在网关层过滤敏感路径和攻击流量
- **减轻服务器负载** - 通过 CDN 缓存和限流减轻服务器压力

#### Nginx 网关配置示例

**禁止敏感路径**：

```nginx
server {
    listen 80;
    server_name your-blog.com;

    # 禁止访问敏感路径
    location ~* ^/(admin|api/admin|\.git|\.env|data) {
        return 403;
    }

    # 限制请求速率
    limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;
    limit_req zone=one burst=20 nodelay;

    # 拦截常见攻击路径
    location ~* \.(php|jsp|asp|aspx)$ {
        return 403;
    }

    location ~* \.(git|svn|hg) {
        return 403;
    }

    # 反向代理到 RustBlog
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

**简单 WAF 规则**：

```nginx
# 检测 SQL 注入
location ~* "(union|select|insert|delete|update|drop|alter|create|truncate)" {
    return 403;
}

# 检测 XSS 攻击
location ~* "<script|javascript:|onload=|onerror=" {
    return 403;
}

# 检测路径遍历
location ~* "\.\./|\.\.\\\|" {
    return 403;
}

# 拦截 User-Agent 中的爬虫
location / {
    if ($http_user_agent ~* (curl|wget|python|bot|spider|crawler)) {
        return 403;
    }
    proxy_pass http://127.0.0.1:8080;
}
```

**限流配置**：

```nginx
# 定义限流区域
limit_req_zone $binary_remote_addr zone=general:10m rate=30r/s;
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

# 应用限流
server {
    # API 路由更严格的限流
    location /api/ {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://127.0.0.1:8080;
    }

    # 其他路径使用常规限流
    location / {
        limit_req zone=general burst=50 nodelay;
        proxy_pass http://127.0.0.1:8080;
    }
}
```

#### 使用 Cloudflare CDN

Cloudflare 提供强大的 CDN 和安全防护功能，可以有效保护您的博客：

**1. 注册 Cloudflare 并添加站点**

- 访问 https://www.cloudflare.com/
- 注册账号并添加您的域名
- 更新域名 DNS 服务器为 Cloudflare 提供的服务器

**2. 配置防火墙规则**

在 Cloudflare Dashboard 中配置以下规则：

**拦截恶意爬虫**：
```
(http.user_agent contains "curl" or http.user_agent contains "wget" or 
 http.user_agent contains "python" or http.user_agent contains "bot") and
(http.uri_path contains "/admin" or http.uri_path contains "/api")
```
操作：Block

**限制 API 请求频率**：
```
(http.uri_path starts_with "/api/")
```
操作：Rate Limit（10 requests/minute）

**禁止访问敏感路径**：
```
(http.uri_path contains "/admin" or http.uri_path contains "/api/admin" or 
 http.uri_path contains "/data")
```
操作：Block

**拦截 SQL 注入尝试**：
```
http.request.body contains "union" or http.request.body contains "select" or
http.request.body contains "drop" or http.request.body contains "delete"
```
操作：Block

**3. 启用 Cloudflare 功能**

- **Always Online** - 服务器离线时提供缓存版本
- **Auto Minify** - 自动压缩 HTML、CSS、JS
- **Brotli** - 使用 Brotli 压缩
- **Security Level** - 设置为 Medium 或 High
- **Challenge Passage** - 15 分钟（通过验证后 15 分钟内无需再次验证）
- **Browser Integrity Check** - 启用浏览器完整性检查

**4. 配置缓存规则**

- 静态资源（CSS、JS、图片）：缓存 1 年
- HTML 页面：不缓存或缓存很短时间（5 分钟）
- API 请求：不缓存
- 管理页面：不缓存，并启用 Cloudflare Access

**5. 使用 Cloudflare Workers 实现高级防护**

创建 Worker 实现自定义逻辑：

```javascript
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request))
})

async function handleRequest(request) {
  // 检测恶意路径
  const url = new URL(request.url)
  const path = url.pathname.toLowerCase()

  // 禁止访问敏感路径
  if (path.includes('/admin') || path.includes('/api/admin') || path.includes('/data')) {
    return new Response('Forbidden', { status: 403 })
  }

  // 检测 SQL 注入
  const body = await request.text()
  if (body.match(/(union|select|drop|delete|update|insert)/i)) {
    return new Response('Forbidden', { status: 403 })
  }

  // 检测 XSS 攻击
  if (body.match(/<script|javascript:|onload=|onerror=/i)) {
    return new Response('Forbidden', { status: 403 })
  }

  // 正常请求转发到源站
  return fetch(request)
}
```

```bash
fs.file-max = 65536

# 优化 TCP 缓存
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216

# 减少交换使用
vm.swappiness = 10
```

**应用配置**：
```bash
sudo sysctl -p
```

### 3. 使用 cgroups 限制内存

使用 cgroups 限制进程内存占用：

**创建 cgroup**：
```bash
sudo cgcreate -g memory:/rustblog
```

**设置内存限制**：
```bash
sudo cgset -r memory.limit_in_bytes=256M rustblog
```

**启动服务**：
```bash
sudo cgexec -g memory:rustblog ./rustblog --enable-cache --cache-backend auto -r
```

### 4. 使用 Docker 部署

使用 Docker 可以更好地控制资源使用：

**Dockerfile**：
```dockerfile
FROM alpine:latest

COPY rustblog /usr/local/bin/rustblog
RUN chmod +x /usr/local/bin/rustblog

EXPOSE 8080

CMD ["rustblog", "--enable-cache", "--cache-backend", "auto", "-r"]
```

**运行容器**：
```bash
docker run -d \
  --name rustblog \
  --memory="256m" \
  --cpus="1" \
  -p 8080:8080 \
  -v $(pwd)/data:/app/data \
  rustblog
```

## 常见问题

### Q1: 如何选择合适的内存分配器？

**A:** 根据场景选择：

| 分配器 | 适用场景 | 内存占用 | 性能 |
|--------|---------|---------|------|
| 默认 | 通用 | 低 | 中等 |
| jemalloc | 高并发 | 中等 | 高 |
| mimalloc | 通用 | 低 | 高 |
| tcmalloc | 高负载 | 高 | 最高 |

### Q2: 启用多个特性会增加内存占用吗？

**A:** 不一定：

- `jemalloc` / `mimalloc` / `tcmalloc` - 只选一个，不增加内存
- `simd` - 不增加内存，提高性能
- `compressed-embed` - 减少二进制大小，略微增加启动时间
- `valkey` - 需要额外的 Valkey/Redis 服务

### Q3: 如何进一步降低内存占用？

**A:** 方法：

1. 使用轻量级配置编译
2. 禁用所有不必要的功能
3. 限制并发连接数
4. 优化图片和资源
5. 定期清理旧数据
6. 使用 cgroups 限制内存

### Q4: 内存占用突然增加怎么办？

**A:** 排查步骤：

1. **检查日志** - 查看是否有错误
2. **检查内存泄漏** - 使用 valgrind 分析
3. **检查动态路由** - 是否有过多路由
4. **检查缓存** - 缓存是否过大
5. **重启服务** - 清理内存

### Q5: 如何在 1G 内存的 VPS 上运行？

**A:** 配置建议：

1. **使用轻量级配置编译**
```bash
cargo build --release --features "mimalloc-alloc,compressed-embed"
```

2. **禁用所有不必要功能**
- Live2D
- 音乐播放器
- 飘字效果

3. **限制并发**
```bash
./rustblog --workers 1 --max-connections 100
```

4. **使用 cgroups 限制**
```bash
sudo cgset -r memory.limit_in_bytes=512M rustblog
```

### Q6: 如何使用 32 位编译进一步降低内存？

**A:** 32 位编译可以降低 40-50% 的内存占用：

1. **添加 32 位目标架构**
```bash
rustup target add i686-unknown-linux-musl
```

2. **编译为 32 位**
```bash
cargo build --release --target i686-unknown-linux-musl --features "mimalloc-alloc,compressed-embed"
```

3. **配置 mimalloc 环境变量**
```bash
export MIMALLOC_PAGE_RESET=1
export MIMALLOC_MAX_EXTENSIONS=8
export MIMALLOC_EAGER_COMMIT=0
```

4. **运行 32 位程序**
```bash
./target/i686-unknown-linux-musl/release/rustblog --enable-cache --cache-backend auto -r
```

**注意事项**：
- 最大内存限制约 4GB
- 需要安装 32 位库支持
- 某些依赖可能不支持 32 位
- 性能可能略有下降
