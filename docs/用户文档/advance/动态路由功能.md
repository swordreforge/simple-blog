# 动态路由功能

RustBlog 的动态路由系统是一个强大的功能，允许您在运行时动态添加、修改和删除路由，无需重启服务。该系统支持零停机热重载、多种路由类型和灵活的存储方式。

## 位置/admin/dyn-routing

## 概述

### 什么是动态路由？

动态路由是指在应用运行时可以动态配置的路由规则。与传统的静态路由不同，动态路由允许您：

- **无需重启** - 添加、修改、删除路由无需重启服务
- **即时生效** - 路由配置更改立即生效
- **灵活管理** - 通过管理界面或 API 轻松管理路由

### 核心特性

- ✅ **零停机热重载** - 路由变更不影响正在运行的请求
- ✅ **高性能匹配** - 基于 Radix Tree 算法，16 分片优化
- ✅ **多种路由类型** - 支持重定向、静态内容、自定义页面等
- ✅ **多存储支持** - 内存、文件、数据库三种存储方式
- ✅ **路由分组** - 支持路由组管理，简化快捷菜单
- ✅ **快捷菜单集成** - 自动集成到快捷操作栏

## 访问动态路由管理

1. 登录管理员账号
2. 点击侧边栏的"管理员设置"
3. 选择"动态路由"标签页

## 路由类型

RustBlog 支持以下路由类型：

### 1. 重定向路由 (Redirect)

将一个路径重定向到另一个路径。

**使用场景**：
- URL 变更时保持向后兼容
- 短链接重定向
- 临时重定向

**配置示例**：
```json
{
  "route_name": "旧链接重定向",
  "route_type": "database",
  "path": "/old-url",
  "handler_type": "redirect",
  "handler_config": {
    "type": "redirect",
    "target": "/new-url",
    "status_code": 301
  },
  "enabled": true
}
```

**状态码说明**：
- `301` - 永久重定向
- `302` - 临时重定向
- `307` - 临时重定向（保持方法）
- `308` - 永久重定向（保持方法）

### 2. 静态内容路由 (Static)

返回静态 HTML、JSON 或其他内容。

**使用场景**：
- 创建自定义页面
- 返回 API 数据
- 创建简单的着陆页

**配置示例**：
```json
{
  "route_name": "关于页面",
  "route_type": "database",
  "path": "/about-custom",
  "handler_type": "static",
  "handler_config": {
    "type": "static",
    "content": "<h1>关于我们</h1><p>这是自定义的关于页面。</p>",
    "content_type": "text/html; charset=utf-8"
  },
  "enabled": true
}
```

**返回 JSON 示例**：
```json
{
  "route_name": "API 版本信息",
  "route_type": "database",
  "path": "/api/version",
  "handler_type": "static",
  "handler_config": {
    "type": "static",
    "content": "{\"version\":\"1.0.0\",\"name\":\"RustBlog\"}",
    "content_type": "application/json"
  },
  "enabled": true
}
```

### 3. 内联模板路由 (Inline Template)

使用内联的 HTML 模板，支持变量替换和条件渲染。

**使用场景**：
- 需要动态内容的页面
- 使用博客变量的自定义页面
- 复杂的自定义页面

**配置示例**：
```json
{
  "route_name": "自定义首页",
  "route_type": "database",
  "path": "/custom-home",
  "handler_type": "inline_template",
  "inline_template": "<h1>{{ title }}</h1><p>{{ content }}</p>",
  "handler_config": {
    "title": "欢迎",
    "content": "这是自定义的首页内容"
  },
  "enabled": true
}
```

### 4. 文件模板路由 (File Template)

使用外部 HTML 模板文件。

**使用场景**：
- 复杂的自定义页面
- 需要外部编辑的页面
- 与现有模板系统集成

**配置示例**：
```json
{
  "route_name": "自定义页面",
  "route_type": "database",
  "path": "/custom-page",
  "handler_type": "file",
  "template_path": "templates/custom-page.html",
  "enabled": true
}
```

## 存储类型

RustBlog 支持三种路由存储方式：

### 1. 数据库存储 (Database)

**推荐**：生产环境使用

- ✅ 持久化存储
- ✅ 支持复杂查询
- ✅ 易于管理
- ⚠️ 性能略低于内存存储

**使用场景**：
- 生产环境
- 需要持久化的路由
- 需要统计和分析

### 2. 内存存储 (Memory)

**最快**：临时重定向使用

- ✅ 最高性能
- ✅ 零延迟
- ❌ 重启后丢失
- ❌ 不支持持久化

**使用场景**：
- 临时重定向
- 测试环境
- 不需要持久化的路由

### 3. 文件存储 (File)

**平衡**：配置管理使用

- ✅ 持久化存储
- ✅ 易于版本控制
- ✅ 可手动编辑
- ⚠️ 需要文件系统权限

**使用场景**：
- 配置管理
- 批量导入/导出
- 需要版本控制的路由

## 路由分组

### 什么是路由组？

路由组允许您将相关的路由归为一组，组中只有一个路由（主要入口）会显示在快捷菜单中。

### 路由组配置

在路由配置中添加路由组信息：

```json
{
  "route_name": "用户中心",
  "route_type": "database",
  "path": "/user/profile",
  "handler_type": "inline_template",
  "group_id": "user_center",
  "is_primary_entry": true,
  "metadata": {
    "group_name": "用户中心模块",
    "menu_icon": "user",
    "menu_order": 10
  },
  "enabled": true
}
```

**字段说明**：
- `group_id` - 路由组 ID（可选）
- `is_primary_entry` - 是否为主要入口（可选）
- `metadata.group_name` - 路由组名称（辅助信息）

### 路由组示例

**用户中心模块**：

```json
// 主要入口（显示在快捷菜单）
{
  "route_name": "个人资料",
  "path": "/user/profile",
  "group_id": "user_center",
  "is_primary_entry": true,
  "metadata": {
    "group_name": "用户中心",
    "menu_icon": "user"
  }
}

// 相关路由（不显示在快捷菜单）
{
  "route_name": "账户设置",
  "path": "/user/settings",
  "group_id": "user_center",
  "is_primary_entry": false
}

{
  "route_name": "通知中心",
  "path": "/user/notifications",
  "group_id": "user_center",
  "is_primary_entry": false
}
```

## API 接口

### 1. 获取路由列表

**请求**：
```
GET /api/admin/dynamic-routes?page=1&limit=20
```

**响应**：
```json
{
  "success": true,
  "data": {
    "routes": [
      {
        "id": 1,
        "route_name": "关于页面",
        "path": "/about-custom",
        "handler_type": "static",
        "enabled": true,
        "priority": 0
      }
    ],
    "total": 1,
    "page": 1,
    "limit": 20
  }
}
```

### 2. 创建路由

**请求**：
```
POST /api/admin/dynamic-routes
Content-Type: application/json

{
  "route_name": "新页面",
  "route_type": "database",
  "path": "/new-page",
  "handler_type": "static",
  "handler_config": {
    "type": "static",
    "content": "<h1>New Page</h1>",
    "content_type": "text/html"
  },
  "enabled": true
}
```

**响应**：
```json
{
  "success": true,
  "message": "路由创建成功",
  "data": {
    "id": 2,
    "path": "/new-page"
  }
}
```

### 3. 更新路由

**请求**：
```
PUT /api/admin/dynamic-routes/2
Content-Type: application/json

{
  "route_name": "更新的页面",
  "route_type": "database",
  "path": "/new-page",
  "handler_type": "static",
  "handler_config": {
    "type": "static",
    "content": "<h1>Updated Page</h1>",
    "content_type": "text/html"
  },
  "enabled": true
}
```

**响应**：
```json
{
  "success": true,
  "message": "路由更新成功"
}
```

### 4. 删除路由

**请求**：
```
DELETE /api/admin/dynamic-routes/2
```

**响应**：
```json
{
  "success": true,
  "message": "路由删除成功"
}
```

### 5. 启用/禁用路由

**请求**：
```
POST /api/admin/dynamic-routes/1/enable
```

或

```
POST /api/admin/dynamic-routes/1/disable
```

**响应**：
```json
{
  "success": true,
  "message": "路由已启用"
}
```

### 6. 测试路由

在创建路由前测试路由配置是否正确。

**请求**：
```
POST /api/admin/dynamic-routes/test
Content-Type: application/json

{
  "route_type": "database",
  "path": "/test-route",
  "handler_type": "redirect",
  "handler_config": {
    "type": "redirect",
    "target": "/target-url",
    "status_code": 302
  }
}
```

**响应**：
```json
{
  "success": true,
  "data": {
    "status_code": 302,
    "headers": {
      "Location": "/target-url"
    }
  }
}
```

### 7. 导出路由

导出所有路由配置。

**请求**：
```
GET /api/admin/dynamic-routes/export
```

**响应**：
```json
{
  "success": true,
  "data": {
    "routes": [...],
    "exported_at": "2026-03-30T12:00:00Z"
  }
}
```

### 8. 导入路由

批量导入路由配置。

**请求**：
```
POST /api/admin/dynamic-routes/import
Content-Type: application/json

{
  "routes": [...]
}
```

**响应**：
```json
{
  "success": true,
  "message": "成功导入 5 条路由",
  "data": {
    "imported": 5,
    "failed": 0
  }
}
```

## 最佳实践

### 1. 路径命名

使用清晰、有意义的路径：

```
✅ 好的路径：
/about
/user/profile
/api/v1/users

❌ 不好的路径：
/a
/u/p
/api/1/u
```

### 2. 路由优先级

使用优先级控制路由匹配顺序：

- 优先级范围：-100 到 100
- 数字越小，优先级越高
- 相同优先级时，按创建顺序匹配

**示例**：
```
具体路径：/user/profile（优先级 0）
通配符路径：/user/*（优先级 10）
全局路径：/*（优先级 20）
```

### 3. 路由分组

使用路由组组织相关路由：

```
用户中心模块：
- /user/profile（主要入口）
- /user/settings
- /user/notifications

博客管理模块：
- /admin/blog/posts（主要入口）
- /admin/blog/categories
- /admin/blog/tags
```

### 4. 重定向策略

选择正确的重定向状态码：

- `301` - URL 永久变更（SEO 友好）
- `302` - URL 临时变更
- `307` - 临时重定向（保持 HTTP 方法）
- `308` - 永久重定向（保持 HTTP 方法）

### 5. 性能优化

- 使用数据库存储（推荐）
- 避免过多动态路由（建议 < 1000）
- 使用路由分组减少快捷菜单项
- 定期清理不使用的路由

## 常见问题

**Q: 动态路由的优先级如何？**

A: 路由优先级（从高到低）：
1. API 路由 (`/api/*`)
2. 页面路由（静态定义）
3. 静态文件 (`/static/*`)
4. 动态路由（兜底路由）

**Q: 路由不生效怎么办？**

A: 请检查：
1. 路由是否已启用
2. 路径是否正确
3. 是否与其他路由冲突
4. 查看日志是否有错误

**Q: 如何调试动态路由？**

A: 方法：
1. 使用"测试路由"功能测试配置
2. 查看浏览器控制台的网络请求
3. 查看服务器日志
4. 使用 `curl` 命令测试

**Q: 动态路由会影响性能吗？**

A: 动态路由性能接近静态路由：
- 16 分片优化，减少锁竞争
- Radix Tree 高效匹配
- 热更新影响 < 5%

**Q: 如何备份路由配置？**

A: 方法：
1. 使用"导出路由"功能导出配置
2. 定期备份数据库
3. 使用版本控制系统管理配置文件

**Q: 路由组如何使用？**

A: 步骤：
1. 为相关路由设置相同的 `group_id`
2. 将其中一个路由标记为 `is_primary_entry: true`
3. 只有主要入口会显示在快捷菜单

## 技术细节

### 零停机热重载

动态路由支持零停机热重载，实现原理：

1. **Arc + RwLock** - 线程安全的路由表
2. **原子操作** - 删除和插入是独立的原子操作
3. **快速切换** - 微秒级的路由更新
4. **优雅降级** - 路由不存在时返回 404

### 性能优化

- **16 分片** - 减少锁竞争
- **Radix Tree** - 高效路径匹配
- **零拷贝** - 使用 Arc 避免克隆
- **缓存优化** - 智能缓存策略

### 路径匹配

支持以下路径模式：

- 静态路径：`/about`
- 参数路径：`/user/:id`
- 通配符：`/api/*`
- 正则表达式：`/posts/\d+`
